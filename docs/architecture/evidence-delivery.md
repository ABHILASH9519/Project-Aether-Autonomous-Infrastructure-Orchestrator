# Durable evidence delivery

Terminal remediation jobs are eligible for a separate archive worker. Migration 3 adds archive state to the existing durable job, without changing the original migration checksums. The worker claims a terminal job with a row lock, serializes the immutable job API document, and derives an object key from SHA-256 of the incident ID. It records successful delivery only after the adapter verifies the object's bytes. Failure is retried with a capped delay of 60 seconds; the remediation outcome is independent of cloud availability.

A crash after upload but before commit may replay the same key and bytes. This is at-least-once delivery, not exactly-once object writes. Archive metadata is not part of the job evidence body. The storage unit test exercises failure, backoff, byte-stable retry and terminal completion. The optional Compose archiver now uses the fixed LocalStack adapter and validates read-back before marking delivery. The integration script checks the uploaded bytes and database checksum without performing any upload. [Automatic archive and outage recovery passed](https://github.com/ABHILASH9519/Project-Aether-Autonomous-Infrastructure-Orchestrator/actions/runs/46131801803).

The authenticated `GET /api/v1/incidents/{id}/archive` endpoint reports not_eligible, pending or archived, delivery attempt count and the confirmed digest/timestamp. Pending may mean the optional cloud profile is disabled. The outage smoke pauses LocalStack, executes an approved repair, confirms a failed archive attempt and an unchanged resolved incident, then unpauses and checks verified delivery. This tests temporary unavailability, not permanent emulator data loss.
